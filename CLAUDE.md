# CLAUDE.md — PRO Ranked Hub

Persistent project context. Read before editing.

## What it is
A visual/interactive toolkit for the **PRO OU** metagame (Pokémon Revolution Online, **Ranked** queue): Role Compendium, Speed Tiers, Viability Ranking, and a Team Builder. Based on several Smogon SM OU threads, filtered down to what's available in PRO. Sprites come from the PMD Sprites Repository (sprites.pmdcollab.org), resolved at runtime via SpriteCollab's GraphQL API.

## Stack
Vite + React, plain JavaScript (no TypeScript), no external state management library — app state lives in small hooks (`src/hooks/`). Plain CSS, one file per component, no CSS Modules. `npm run dev` / `npm run build` / `npm run preview`. Deploys automatically on push to `main` via `.github/workflows/deploy.yml` (GitHub Actions → GitHub Pages).

**This replaced a single-file `.dc.html` (Design Component) app generated by the Claude Design visual editor.** That migration was a deliberate, one-way decision: the visual editor only edits `.dc.html` as a single template+logic+CSS file, which didn't scale past 3 tabs' worth of hand-maintained code. `legacy-dc/` holds the original `.dc.html`/`index.html`/`support.js` (and a frozen copy of the data/logic it imported) as a historical, no-longer-edited record — **don't propose deleting it**, but also don't try to keep it in sync with `src/` anymore; that rule from the old single-file era no longer applies.

## Files
- `src/data/` — the data you edit:
  - `src/data/roles-data.js` — **the single source of role data** (`SECTIONS`: categories, roles, Pokémon).
  - `src/data/viability-data.js` — `VIABILITY`, the master ranking; a name in a role that isn't here is ignored.
  - `src/data/sprites.js` — `SPRITE_API`, `FORM_SUFFIXES`, `NO_SPLIT_HYPHEN` (sprite name/form resolution constants).
- `src/lib/` — pure, stateless functions (no React, no `this`): `viewStyles.js`, `spriteResolve.js`, `speedCalc.js`, `vrLogic.js`, `rolesLogic.js`, `teamLogic.js`, `changelog.js`, `exportCard.js`. Business logic goes here first; components should mostly wire these functions to UI, not reimplement them inline.
- `src/hooks/` — state + side effects: localStorage persistence (`useLocalStorage`, and the `useVr`/`useRoles`/`useTeam`/`useTheme` built on it), network fetching (`useSpeeds`, `useSprites`), and cross-cutting UI state (`useToast`, `useModal`, `useHashTab`, `useScrollSpy`, `useExport`).
- `src/components/` — one folder per tab (`roles/`, `speed/`, `vr/`, `team/`), plus `layout/` (header/tabs/footer) and `shared/` (mon detail drawer, confirm modal, toast, export drawer, print sheet, the `MonTile`/`SpriteImg`/`SearchBox` primitives reused across tabs).
- `src/styles/global.css` — design tokens (`:root` vars, `[data-theme="dark"]`, `@media print`) and the few page-wide/responsive rules. `src/styles/tiles.css` — tile/badge/corner/chip/tab states shared by the Roles and VR grids.
- `legacy-dc/` — frozen historical `.dc.html` app. Not part of the live site, not edited.

## Important rules
- **Data lives only in `src/data/roles-data.js`.** Never inline the list back into a component — the user edits the data file directly.
- **PRO availability:** there are NO Tapus, no Magearna and no Ultra Beasts (except **Blacephalon**). Don't reintroduce them. When touching lists, respect what actually exists in PRO.
- **Keep the editorial look** (beige paper `#f1ece1`, ink, brick red `#cf3a22`; Bricolage Grotesque / Space Grotesk / Space Mono). The user tried a retro version and rejected it. Don't redesign unprompted.
- Everything written in this repo — UI, docs, code comments, commit messages — is in **English**. Conversation with the user stays in Portuguese.
- `vite.config.js`'s `base: "/pro-role-compendium/"` must match the GitHub repo name — update it together if the repo is ever renamed.

## Data format (`src/data/roles-data.js`)
- `SECTIONS`: array of `{ id, title, tag, roles: [...] }` — each block is a tab (order = on-screen order; "All" is automatic).
- Role: `{ name, move, mons: [...] }`.
- `mons` entry: `"Name"` **or** `{ name, note }` — `note` shows the specific move/ability that Pokémon uses to fill the role (red tag on the tile + in the drawer). Strings and objects can coexist.

## Technical details to preserve
- **Sprite loading** (`src/hooks/useSprites.js` + `src/lib/spriteResolve.js`): batches names by shared species (12 per GraphQL call, sequential — don't hammer SpriteCollab), permanently blacklists a name that fails resolution for the session. `src/components/shared/SpriteImg.jsx` handles the per-`<img>` retry (4 attempts, linear backoff) and placeholder-on-failure. This is a simplified, idiomatic-React rewrite of the original `pump()` — the original's DOM-reuse workaround (React recycling an `<img>` across DC's own tab-switch quirk) doesn't apply here; a real `key` prop already forces a remount. Don't reintroduce that complexity.
- **Edit mode is a hidden gate**: only `?edit=1` (or `#edit`) in the URL enables it (`useHashTab.js`), with no UI toggle. Preserve this — it's intentional (edits are a "propose a change" flow, not a public editing feature).
- **`useExport.js` reads the raw source text of `roles-data.js`/`viability-data.js` via Vite's `?raw` import suffix**, not `fetch()` — those files aren't served as static assets in the production build, so `?raw` (bundled at build time) is required for the "copy updated file" feature to work outside of dev.
- Six `localStorage` keys carry over from the original app unchanged: `pro-roles-pending-edits`, `pro-roles-vr-draft`, `pro-roles-team`, `pro-roles-sprite-cache`, `pro-roles-speed-cache`, `pro-roles-theme`.
